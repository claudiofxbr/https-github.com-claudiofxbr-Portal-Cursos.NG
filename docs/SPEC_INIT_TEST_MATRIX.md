# Matriz de Testes Web SPEC-INIT-001 (PortalCursos.NG)

**Regra de Inicialização e Recuperação de Sessão**

Esta matriz formaliza a adaptação web dos casos de teste **T-01 a T-10** da especificação **SPEC-INIT-001**, aplicando as três decisões de produto tomadas pelo usuário:

1. **Portão vira parte da tela de login**: O portão de código de acesso (`PORTAL_GATE_PASSCODE = 2026`) está integrado diretamente no formulário da tela de login como primeira etapa (`step = 'gate' -> 'auth'`), nunca como tela separada bloqueando rotas ou o bootstrap da aplicação.
2. **Rota `/reset-password` é exceção documentada**: Rota pública pré-autenticação para redefinição de credenciais via token de e-mail.
3. **Arquitetura de sessão em duas camadas**:
   - **Access Token PocketBase curto em memória**: Não é persistido em `localStorage` nem em `sessionStorage`. Fica mantido na instância em memória do SDK (`AsyncAuthStore`), vulnerável a XSS persistente eliminada.
   - **Refresh Token persistente em Cookie seguro**: Cookie `portal_refresh_token` gerado pelo backend sob `HttpOnly; Secure; SameSite=Lax; Path=/backend/v1/auth`, com hash persistido na collection `auth_sessions`.
   - **Hidratação silenciosa pós-F5**: Ao carregar a página (F5 ou abertura), o frontend invoca `/backend/v1/auth/refresh`. O navegador anexa o cookie seguro automaticamente, o backend valida o token, gera novo JWT curto do PocketBase e rotaciona o cookie de refresh. Se falhar, o app permanece no estado não autenticado e exibe o login com portão integrado.

| **T-07** | **Cookies Bloqueados ou Ausentes no Navegador**              | Usuário com restrição severa de cookies de terceiros/primeiros ou requisições bloqueadas.                                           | A tentativa de refresh silencioso falha; o app exibe a tela de login. ## Verificação de Armazenamento (Critério Anti-XSS)

- **`localStorage`**: Não contém tokens de sessão do PocketBase (`pb_auth`), nem credenciais salvas, nem chaves de sessão `portal_*`. Chaves legadas são higienizadas na inicialização (`cleanupLegacyStorage()`).
- **`sessionStorage`**: Utilizado estritamente para estado de UI volátil (aba ativa durante navegação), sendo descartado imediatamente em caso de crash (Error Boundary) ou logout.
- **Cookies**: O cookie de sessão `portal_refresh_token` possui as flags `HttpOnly`, `Secure` (em produção/HTTPS) e `SameSite=Lax`, tornando-o inacessível via `document.cookie` e prevenindo exfiltração via scripts maliciosos.
